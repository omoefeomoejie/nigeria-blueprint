# Investigation SOP — v0.1

The repeatable sequence for investigating one node. Derived from how Node 1
actually unfolded — including the wrong turns, because the wrong turns are what
make the sequence worth writing down.

## The sequence

1. **State the node as one falsifiable question.** Not "fix revenue" but "what %
   of state revenue is IGR vs. FAAC, and which states moved that balance without
   structural luck?" If it can't be answered with a number or a named case, sharpen
   it until it can.

2. **Pull real data before theorising further.** First contact with reality comes
   early, not after the framework is built. (The whole engine exists because this
   step was skipped for too long.)

3. **Run the candidate cases through the Comparative Statecraft Engine.** Confounding
   check → classify the gain → weight the sources → state what's owed.

4. **Assign an Evidence Standard status to every claim.** Certified / Contested /
   Confounded / Owed. No claim travels into the Blueprint above its status.

5. **Name the single owed fact.** End every node with the one search or source that
   would move the weakest important claim up a status. That becomes the next action.

6. **Write the Mistakes.md entry before moving on.** What did we believe entering;
   what was wrong; why were we fooled; what rule did it add. (See Lessons Learned.)

7. **Version the engine.** Any rule the node earned updates the relevant skill from
   vN to vN+1, with the node cited as origin. No earned rule left uncommitted.

## A discipline note carried from Node 1
Drilling one case to certification is worth more than surveying ten to the
"contested" level. Depth over breadth until a mechanism is proven; then breadth
to test transferability.

---

**Origin:** Node 1 (Revenue Structure). Steps 2 and 6 exist specifically because
Node 1 went wrong without them — theory ran ahead of data (fixed by step 2), and
the session's most valuable output was nearly lost to memory (fixed by step 6).
